## Shape

`ai chat` keeps named, repo-local **threads**: conversations that outlive harness sessions and harnesses. Coding agents (Claude Code, pi, Codex) run in their own harness; `ai chat` copies their sessions into the thread, rolls the thread up into a zoomable summary tree, and compresses the agent's context into a view of the whole thread when the session compacts.

A user keeps a few long-lived threads per repo, one per role (`developer`, `reviewer`, `researcher`). Sessions outside any thread are untouched.

## Threads and sessions

- A session is tracked only while **attached** to a thread.
- An attached session always compacts with `ai chat`: `/compact`, auto-compaction and `/ai compress` all produce the `ai chat` view. `ai chat detach` returns `/compact` to the harness.
- `/clear` keeps its meaning: a new, unattached session. The cleared session's exchanges stay in the thread.
- Compaction happens only when the user or agent asks for it, or the harness auto-compacts. Starting or resuming never compacts a running context.
- A thread spans harnesses. Each harness keeps its own session files; the thread holds the exchanges of all of them.

## Commands

From a terminal:

| Command | Effect |
|---|---|
| `ai chat <harness> <name> [-- args]` | New harness session attached to `name`. New thread: empty session. Existing thread: fresh session seeded with the view, its only context. |
| `ai chat resume <name>` | Continue the thread's latest native session (`claude --resume <id>`), full context, attached. If it cannot be resumed (transcript deleted), a fresh session seeded with the view. |
| `ai chat resume` | List threads: name, harness, last activity, branch tips. |

From inside a session (the agent's shell, or the user with `!`):

| Command | Effect |
|---|---|
| `ai chat attach <name>` | Attach the current session (`CLAUDE_CODE_SESSION_ID`, `PI_SESSION_ID`, `CODEX_THREAD_ID`) to `name`, creating it if new. Its whole history is ingested, grafted onto the thread's tip. |
| `ai chat detach` | Stop tracking; `/compact` is native again. Re-attaching catches up from the transcript. |
| `ai chat resume` | Print the attached thread's view (paged). |
| `ai chat zoom <id>` | Open a line: thread node → exchange lines → chunk lines → raw entries (paged). |

Inside a Claude Code session the mod adds `/ai compress`, `/ai attach <name>`, `/ai detach`, and an agent tool that queues a compaction for when the turn ends.

Internal (called by hooks and the mod): `ai chat sync`, `ai chat compact`, `ai chat nap`. Contract below.

Subagents share the parent's session id in Claude Code and cannot be told apart; the attach instruction says only the main agent attaches.

## Data model

- **Item**: one normalised source entry: user message, assistant text, tool call, tool result, or marker. Records harness, session, source entry id, parent item, time, content, and the raw source lines verbatim. Thinking is dropped. Harness-injected user entries (tool results, hook context, `isMeta`, AGENTS.md echoes) are not user messages.
- Items form a **tree** by parent links. A branch is a path from the root. Rewinds, edits, pi `/tree`, Codex rollback and two sessions on one thread all add branches; nothing is removed.
- **Step**: assistant text, if any, plus the tool calls and results that follow it, up to the next assistant text. A final text-only reply is a step. Example: "I'll check the config", Read ×3, Grep is one step; "Found it, fixing", Edit, Bash is the next; "Done: …" the last.
- **Exchange**: a user message and the steps that answer it, up to the next user message on the branch. A message sent mid-run opens a new exchange. An exchange is closed once a user message follows it.
- Ingest is idempotent by source id: a resumed session, a compacted one (same file) and a fork (copied prefix, same ids) add only new entries.
- Claude Code parallel tool calls branch the transcript's uuid tree; the adapter reattaches results by `tool_use_id`. Only a new user or assistant entry on an older parent is a branch.
- Native summaries (`compact_boundary`/`isCompactSummary`, Codex `compacted`, pi `compaction`) are markers, never content. Compaction does not end a session's chain: the adapter follows `logicalParentUuid`.

## Roll-up

All summaries are written by the compactor (cheap model via `claude -p`, as in `ai memory`); code only segments and clips.

1. **Exchange line** (≤512 B): one call over the whole exchange, when its clipped rendering fits the input budget (start 48 KB; tune). This is the `<user>:<ai>` pair. Most exchanges (median 2 steps, a few KB) take this path. A rendering that fits 512 B is its own line, no call.
2. **Chunks**, only for an exchange over the budget: its steps are cut into consecutive chunks, greedily from the exchange start, each up to the budget, cut only between steps. One call per chunk writes a chunk line (≤512 B); one more call over the chunk lines writes the exchange line. A single step over the budget is cut between tool calls.
3. **Binary tree over exchanges**: aligned pairs along a branch, `<1-2>`, `<3-4>`, then `<1-4>`, up.

- Clipping: each tool output to its head and tail (start 4 KB per output; tune). Raw stays whole and zoomable.
- Keys: a line is keyed by its level and the last item it covers; that item's ancestors fix its range. Lines over a shared prefix are the same record for every branch; lines past a fork belong to their branch. Summaries never merge across branches. Built once, never rewritten.
- Prompt (prose, OptChat's priorities): user words near verbatim; then lasting effects, decisions and failures; then findings; least of all tool steps. Copy paths, commands, hashes and errors exactly. For file reads, say what was examined and found, with paths and line numbers, never the code. For commands, outcomes, errors and numbers. For searches, where the matches were. A finding names the step that holds its detail, so a line points to where to zoom.
- **Background compactor**: builds lines as exchanges and chunks close, woken by `sync`. On by default for attached sessions; config sets the model and can switch it off. One per thread (lock).

## View

What `ai chat compact` and `ai chat resume` print:

1. A short instruction (OptChat's): the view is the thread's memory; zoom a line before acting on it; say in replies what was learned, since summaries keep little tool output.
2. **Fold** over the closed exchanges of the current branch: the corrected OptChat fold (due = (T−last)/2^l, batched, persisted). Older history at coarser levels, each line with its id.
3. **User rail**: the newest user messages verbatim (~8 KB).
4. **Current exchange**: its chunk lines, its last steps raw.

Budget: `VIEW` bytes (start 128,000, OptChat's). Unbuilt lines fall back to their children or a placeholder; `compact` waits for the lines the fold needs, with a timeout.

## Storage

- Repo-local git: one ref per thread, `refs/ai/chat/<name>`, in the repo's common git dir. Moves with the repo, shared across worktrees, never pushed automatically.
- Same machinery as `ai memory`: commit per mutation, CAS on the ref, `format` blob (format 1), named headers, a compactor lock per thread.
- Contents: items (append-only, thread-local sequence numbers, parent links), raw source lines, lines keyed by level and last item, session bindings (harness, session id, transcript path, graft item, attached or detached).
- Harnesses delete transcripts (Claude Code after 30 days); the thread keeps its own copy.
- Raw items carry tool output and may carry secrets. Sharing a thread is a later explicit command with redaction.

## Contract: harness glue ↔ `ai chat`

Every command takes `--harness <claude|pi|codex> --session <id> [--transcript <path>]`; without them it reads the harness's environment. Exit 3 means the session is not attached, with no output.

- `ai chat sync`: ingest new entries; wake the background compactor. Fast; called on every turn end. Unattached: exit 3 at once.
- `ai chat compact`: sync, build the lines the view needs (waiting), print the view on stdout. The Claude mod answers `session.compact` with it. On any failure exit non-zero with the reason on stderr; the mod then falls back to native compaction and shows the reason.
- `ai chat attach <name>` / `ai chat detach`: as above; the mod passes the session explicitly.
- `ai chat nap --thread <name>`: background compactor, detached, spawned by `sync`.

## Harness integration

**Claude Code**: one plugin (installed globally, e.g. `CLAUDE_CODE_PLUGIN_DIRS`, shipped by the flake):
- Mod `session.compact` (manual and auto): attached → answer with `ai chat compact`; unattached (exit 3) → native.
- Mod command `/ai <compress|attach <name>|detach>`; `compress` runs `/compact` deferred (`$.clock.after` + `$.command.run`). Fallback name `/ai-compress` if a command cannot take a subcommand.
- Mod tool for the agent: queue `/compact` for the end of the turn.
- Sync on turn end (mod event or a Stop hook).

**pi** (layer 3): a global extension. Attached sessions: `session_before_compact` returns the view; `/ai compress`, `/ai attach`, `/ai detach` commands. Launch with `pi --session-id <id>`.

**Codex** (layer 3): no way to replace the native summary. Global hooks: Stop syncs; SessionStart(`compact`) injects the view after Codex's own summary (`additionalContextLimit` raised). No session-id flag: the launcher starts Codex with the prompt "Run `ai chat attach <name>`".

## Layers

1. Claude Code end to end: old `ai chat` removed, Claude adapter, thread store and sync, roll-up compactor, view, CLI, plugin with mod.
2. `grep` over raw, chunk/exchange lines and nodes; files-and-commits block in the view.
3. pi extension; Codex adapter and hooks.
4. Evaluation on the user's logs: probe questions after compaction (Factory method), `ai chat` view against native compaction and digest-only masking. Prompt, clip and budget changes follow the data.
