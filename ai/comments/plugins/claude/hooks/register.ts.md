# plugins/claude/hooks/register.ts

The Claude Code side of `ai chat` (design: `ai/research/20261014T002322---chat-design.md`; mod findings: `20261014T202206---chat-launch-attach.md`). Claude Code 2.1.300; the mods API is early access.

- Load per process: `claude --plugin-dir plugins/claude`, or for every session `CLAUDE_CODE_PLUGIN_DIRS=<abs path>` (environment, or `env` in `~/.claude/settings.json`). `ai` is resolved from the session's `PATH`.
- Plugin name `ai`: the command is `/ai`, the tool `mcp__ai__compress`, the state key `ai.transcript`.
- `/ai <sub>` is one command: `command.run` hands the rest of the line as `e.args`, so no `/ai-compress` fallback is needed.
- Transcript path: `$` has the session id but not the transcript path. `classic.SessionStart` (startup, resume, clear, compact) carries it; it goes to `$.state`, which outlives a module reload. `classic.Stop` carries both, so sync reads them from `e`.
- Seed: on `classic.SessionStart` with `source: startup`, `ai chat compact` for the new session; its stdout is appended to the hooks' `additionalContext`. The launcher (`ai chat claude`, and `ai chat resume` when it falls back) binds a session before it starts, with no item of its own, so `compact` prints the view of the thread up to the session's graft; an unattached session exits 3, a session on a new thread prints nothing, and either starts as it would. Other sources never seed: `resume` replays the seed from the transcript (it is stored there as a `hook_additional_context` attachment, which the adapter drops, so sync never ingests it), `clear` is an unattached session, `compact` already carries the view. A compaction drops the seed with everything else.
- Seed size: a mod's `additionalContext` is not cut at the 10,000 characters a settings hook's output is: 250,000 characters were stored whole, and a 130,000-character seed reached the model whole (haiku answered markers from both ends; 47,182 input tokens). The view is at most 128,000 bytes, so one entry, no paging.
- `session.compact`: exit 0 with a view answers `{ messages: [view as one user message] }` without `next`, so the summarizer never runs (`compact_boundary`, ~20 ms, no model call). Exit 3, an empty view (a thread with nothing yet) and failures call `next(e)`: native compaction; a failure also writes the stderr reason to the transcript (`$.ui.log`, `ui_log` under `-p`). Every trigger (`manual`, `auto`, `plugin`, `precompute`) is handled the same. A subagent's own compaction (`agentId`) stays native: the thread view is the main conversation's. The view's user entry has no `origin`, so sync drops it; the boundary becomes a compaction marker.
- Flush: Claude Code buffers transcript writes for up to a second (`flushIntervalMs: 1000` in 2.1.300; measured 50–220 ms). A compaction queued at turn end (agent tool, `/ai compress` typed during a turn) ran 36 ms after the turn's last entry; its sync missed the final reply, so the view lacked it, and turn-end syncs missed it too. `session.compact` therefore sleeps `FLUSH_MS` (1,100 ms) before `ai chat compact` (an auto compaction mid-turn has the same race), and the Stop sync runs `FLUSH_MS` later (`$.clock.after`). `session.end` syncs once more after the engine's end step, for a session that exits within that second; it also covers `/clear` and `-p`.
- Answering without `next` also skips the built-in `cc-plugin-agents-md` hook beneath, which marks nested instruction files for re-attachment after a compaction. After an `ai chat` compaction, nested `CLAUDE.md`/`AGENTS.md` files read before it are not re-attached until something else resets that plugin's state. No mod API lets a user-tier hook run the built-ins but skip core.
- On `auto` the prompt that triggered it is already in the transcript and inside the compacted span: the view must carry the open exchange, or the model sees no question.
- `/compact` from the mod: `$.command.run({ command: 'compact' })` from `$.clock.after(0, …)`. Called inside a `command.run` or `tool.call` hook it is refused (it would compact under the turn the hook holds). `$.session.compact()` skips the calling plugin's own `session.compact` hook, so it would compact natively. A `$.command.run` made during a turn waits for the turn to end; that is how the agent tool queues compaction.
- The agent tool probes with `ai chat sync`: exit 3 means unattached (nothing queued); exit 0 also ingests before the compaction. It is left deferred (behind ToolSearch) so unattached sessions carry no schema.
- Turn-end sync is a mod `classic.Stop` hook, not a `hooks.json` command hook: it has the session id and transcript path without parsing stdin. It returns at once; the sync runs on the timer.
- `$.process.run` reads the whole output until the child exits: `ai chat sync` must detach `nap` from its stdout and stderr, or it holds the call. Its timeout is 30 s by default; `compact` and `attach` get the 10-minute maximum.
- An interactive `--plugin-dir` session writes the engine's type declarations into `.claude-plugin/types/`; `.gitignore` keeps them out.
- Tests (`claude plugin test plugins/claude`) stub `process.run` and the clock beneath the plugin; they need no model and no `ai`.
