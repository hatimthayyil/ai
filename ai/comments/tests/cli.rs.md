# tests/cli.rs

Binary tests. `Sandbox` isolates every run: `HOME`/`XDG_CONFIG_HOME` in the temp dir, `GIT_CONFIG_NOSYSTEM`, `GIT_CEILING_DIRECTORIES` at the temp dir's parent (a stray `/tmp/.git` appears from outside these tests; repo discovery must never reach it), agent/git identity env removed, and `AI_MEMORY_NAP=0`, `AI_NOTES_NAP=0` so no command starts a background nap (a real `claude` on `PATH` would be called). Test git runs disable auto-maintenance (its `maintenance.lock` would race the "nothing written outside the store" listing).

`a_note_naps_in_the_background` turns the trigger on with a fake `claude` shell script first on `PATH`, answering every stream-json message with a fixed `result`: two 400-byte notes need a model merge, and the detached nap builds `0+2` within the deadline, recording agent `claude-code`, model `sonnet`, the script's `session_id` and the store's origin. Provenance, filters and `show` run here since only the binary reads cwd and env.

`a_note_from_stdin_is_summarised_in_the_background`: `ai notes add` with its body on stdin and the store at its default (`~/.ai/notes` in the sandbox home); a fake `claude` replies `scope\n\ngist`, and the detached nap commits both summaries, leaving a clean work tree.

`a_chat_turn_end_to_end_with_a_fake_claude`: `ai chat` on a pipe with a fake `claude` (bash) on `PATH` that records argv, env, the system prompt file and its first message: one prime then one turn, identical argv, `DISABLE_PROMPT_CACHING` only on the prime, `dontAsk` + allowlist, `--mcp-config` pointing at this binary and memory, the sandbox HOME's CLAUDE.md last in the prompt, identical view blocks (marked only in the prime), the logged user/tool (call and result)/ai, provenance, no follow-up turn logged. Then `ai chat mcp` answers JSON-RPC over stdio on the result.

`Sandbox::fake_claude` installs both fakes the same way as chat's `fake` (see `ai/comments/src/chat/session.rs.md`): `bash` resolved from `PATH` for the shebang, the executable written by a `cp` child to avoid ETXTBSY.

`Tui`: `ai chat` on a pseudo-terminal (libc `openpty`, master close-on-exec so only the test holds it), answering the cursor-position and device-attribute queries crossterm makes at startup. `a_closed_terminal_ends_the_tui` closes the master and requires an exit within 2 s (before the fix crossterm spun forever on the hung-up tty and the chat never exited); `sigterm_ends_the_tui_idle_priming_or_in_a_turn_and_restores_the_terminal` sends SIGTERM idle, while priming hangs, and while a turn hangs, and requires a clean exit that turns bracketed paste off. A failing wait SIGKILLs the child, and `Drop` kills it too, so a failure never leaves a chat behind.

`parallel_processes_lose_nothing` asserts the log is in `ts` order; it was flaky (~1 in 4) until the store stamped messages inside the mutation (store.rs.md, Time order). Provenance checks grep's default (date header, then `id|text`) and `--time -o origin,repo,kind`. The chat test's view and logged labels have bare notes and bare one-message ids (`0|the code word is papaya`).

Usage log: `every_command_logs_one_usage_line` runs wake, notes (one refused), zooms (one bad id), grep with flags and `--before`, and show from a git work tree with `AI_AGENT`/`AI_MODEL`/`AI_SESSION`, then checks each JSON line (cmd, args as typed, ok and error, lines and bytes, provenance, ts) and `stats --by agent`'s exact output. `parallel_reads_log_whole_lines`: 16 processes append 10 kB lines; every line parses. `an_unwritable_usage_log_fails_nothing`: `usage.jsonl` as a directory; note and wake still succeed. `nothing_is_written_outside_the_store_but_the_root_cache`: the store holds `usage.jsonl`; outside it only the work repo's `.git/config` changes, gaining `ai.root`.

Format upgrade. `tests/fixtures/memory-v1.bundle`: a format-1 store written by the 0.7.0 release binary (built from tag `v0.7.0`): 4 imported notes, 12 notes from a git repo with remote `acme/widget` and `AI_AGENT`/`AI_MODEL`/`AI_SESSION` set (every third one 270 bytes, so merges need the model), then `nap` with a fake `claude` answering `summary <md5 of the request, 8 hex>`; 16 messages, 31 nodes, two of them model-built (`4+4`, `8+8`). A bundle keeps the store exactly as 0.7.0 committed it, history included, in one file; `Sandbox::v1_store` fetches it into a bare repo. `tests/fixtures/memory-v1.golden`: `$ <args>` lines, each followed by its stdout, recorded by this ai's last format-1 build on the fixture (wake, wake with every field, zoom, grep -t, show of a message, a model node and a free node, config, a folded wake with `-o session`); the `show` of a message gained the `root    -` line by hand.
- `a_format_1_store_upgrades_once_and_reads_as_before`: the first command prints only the upgrade line on stderr and the golden wake; one commit `upgrade format 1 -> 2` on the old head, `format` = 2; every golden command matches with empty stderr and the ref unmoved; the tree has the same paths plus `format`; every message text and every node text equals the format-1 one.
- `concurrent_opens_upgrade_once`: 8 `wake`s at once; all print the golden wake, exactly one announces the upgrade, the others at most wait, and the ref holds one upgrade commit.
- `a_newer_format_is_refused_before_any_write`: a commit with `format` 3 made by git plumbing; note, wake, nap, show and init fail with the refusal and the ref stays.
- `the_root_is_the_default_branchs_first_commit`: a note from an orphan branch records `main`'s first commit.
